# OpenShift Routes with Shared Host Path-Based Multiplexing

## Overview

This pattern exposes multiple services through a single hostname using OpenShift Routes with path-based routing. The UI, API, health, docs, and admin endpoints all share one hostname with different path prefixes, while Keycloak gets a separate prefixed hostname. This avoids the need for multiple DNS entries or a single reverse proxy ingress.

## Pattern Description

Six OpenShift Routes are created from a single template file, all sharing a common `sharedHost` value. The UI Route handles the root path, while the API Route handles `/api`, health handles `/health`, docs handles `/docs`, and admin handles `/admin`. Keycloak gets its own Route with a hostname prefixed by `keycloak-`. The `sharedHost` is typically auto-generated from the project name, namespace, and cluster domain (e.g., `mortgage-ai-mortgage-ai.apps.cluster.example.com`). A three-level fallback determines the hostname: `sharedHost` > `ui.host` > empty (auto-assigned by OpenShift).

## Implementation

### Shared Host with Path-Based Routing

All Routes use the same hostname, differentiated by path:

```yaml
# deploy/helm/mortgage-ai/templates/routes.yaml (UI Route)
apiVersion: route.openshift.io/v1
kind: Route
metadata:
  name: {{ .Values.ui.name }}-route
spec:
  {{- if .Values.routes.sharedHost }}
  host: {{ .Values.routes.sharedHost }}
  {{- else if .Values.routes.ui.host }}
  host: {{ .Values.routes.ui.host }}
  {{- end }}
  to:
    kind: Service
    name: {{ .Values.ui.name }}
  port:
    targetPort: http
  tls:
    termination: edge
    insecureEdgeTerminationPolicy: Redirect
```

### API Route with /api Path Prefix

```yaml
# deploy/helm/mortgage-ai/templates/routes.yaml (API Route)
apiVersion: route.openshift.io/v1
kind: Route
metadata:
  name: {{ .Values.api.name }}-route
spec:
  {{- if .Values.routes.sharedHost }}
  host: {{ .Values.routes.sharedHost }}
  {{- else if .Values.routes.api.host }}
  host: {{ .Values.routes.api.host }}
  {{- else if .Values.routes.ui.host }}
  host: {{ .Values.routes.ui.host }}
  {{- end }}
  to:
    kind: Service
    name: {{ .Values.api.name }}
  port:
    targetPort: http
  path: /api
  tls:
    termination: edge
```

### Keycloak Route with Prefixed Hostname

Keycloak gets a separate hostname by prepending `keycloak-` to the shared host:

```yaml
# deploy/helm/mortgage-ai/templates/routes.yaml (Keycloak Route)
{{- if .Values.keycloak.enabled }}
apiVersion: route.openshift.io/v1
kind: Route
metadata:
  name: {{ .Values.keycloak.name }}-route
spec:
  {{- if .Values.routes.sharedHost }}
  host: {{ printf "keycloak-%s" .Values.routes.sharedHost }}
  {{- end }}
  to:
    kind: Service
    name: {{ .Values.keycloak.name }}
  port:
    targetPort: http
  tls:
    termination: edge
    insecureEdgeTerminationPolicy: Redirect
{{- end }}
```

### Hostname Auto-Generation in deploy.sh

The deploy script auto-generates the shared hostname from the cluster domain:

```bash
# scripts/deploy.sh (excerpt)
CLUSTER_DOMAIN=$(oc whoami --show-server 2>/dev/null \
    | sed -E 's|https://api\.([^:]+).*|apps.\1|' || echo "")

SET_ARGS+=(--set "routes.sharedHost=$PROJECT_NAME-$NAMESPACE.$CLUSTER_DOMAIN")
```

## Configuration

- **Key settings:** `routes.enabled` (default: true) toggles all Routes; `routes.sharedHost` is the shared hostname (typically auto-set by deploy.sh); `routes.ui.host` is a per-service fallback; `routes.api.host` is ignored when sharedHost is set
- **Defaults:** TLS termination is `edge` with `insecureEdgeTerminationPolicy: Redirect`; all Routes use `wildcardPolicy: None`; the API host falls back from `sharedHost` to `api.host` to `ui.host` (three-level cascade)
- **Dependencies:** OpenShift cluster with Route support; the deploy.sh script depends on `oc whoami --show-server` for cluster domain discovery; wildcard DNS must be configured for the `apps.*` domain

## Gotchas

- The API Route uses `path: /api` which means the nginx reverse proxy in the UI container also forwards `/api/` to the backend -- when accessed via the Route, traffic goes directly to the API Service without the nginx proxy (see `deploy/helm/mortgage-ai/templates/routes.yaml` line 62 and `packages/ui/nginx/default.conf.template`)
- Five separate Route objects (`ui-route`, `api-route`, `api-health-route`, `api-docs-route`, `api-admin-route`) all share the same hostname -- OpenShift's HAProxy router handles path-based routing across these Routes (see `deploy/helm/mortgage-ai/templates/routes.yaml`)
- The Keycloak hostname uses `printf "keycloak-%s"` to prepend `keycloak-` to the shared host -- this means a wildcard DNS entry must cover the `keycloak-` prefix (see `deploy/helm/mortgage-ai/templates/routes.yaml` line 193)
- The `routes.api.host` value comment says "Ignored - uses sharedHost or ui.host" but the template actually checks `api.host` as a middle fallback between `sharedHost` and `ui.host` (see `deploy/helm/mortgage-ai/values.yaml` line 111 vs template line 52-55)
- The auto-generated KEYCLOAK_ISSUER in the Secret template uses the same `keycloak-` prefixed hostname pattern, ensuring JWT validation matches the external Route hostname (see `deploy/helm/mortgage-ai/templates/secret.yaml` lines 26-28)
