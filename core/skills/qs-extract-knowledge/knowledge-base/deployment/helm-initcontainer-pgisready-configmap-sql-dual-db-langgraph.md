# InitContainer with pg_isready Wait and ConfigMap-Mounted SQL for Dual Databases

## Overview

A Helm deployment pattern where the backend pod uses an initContainer that (1) polls PostgreSQL with `pg_isready` until the database is available, then (2) runs an idempotent SQL initialization script mounted from a ConfigMap. The SQL script creates two separate databases (`aiq_jobs` and `aiq_checkpoints`), application tables in `aiq_jobs`, and LangGraph checkpoint tables in `aiq_checkpoints`. The ConfigMap is auto-generated by a dedicated Helm template that reads from a `files/` directory.

## Pattern Description

The pattern solves the chicken-and-egg problem of PostgreSQL needing to be ready before the backend can connect, while also ensuring database schema is initialized before the application starts. The init script is kept in the Helm chart's `files/` directory (source of truth), rendered into a ConfigMap by a dedicated template, and mounted into the initContainer. Credentials come from a Kubernetes Secret via `secretKeyRef`.

## Implementation

### InitContainer in Values

The initContainer is defined in the backend app's values, using `bitnami/postgresql` as the init image for access to `pg_isready` and `psql`.

```yaml
apps:
  backend:
    initContainers:
    - name: db-init
      image: bitnami/postgresql:latest
      command:
      - sh
      - -c
      - |
        echo "Waiting for postgres..."
        until pg_isready -h aiq-postgres -U $(DB_USER_NAME) -d aiq_jobs; do
          sleep 2
        done
        echo "Running init script..."
        psql -h aiq-postgres -U $(DB_USER_NAME) -d aiq_jobs \
          -v db_user=$(DB_USER_NAME) -f /db-init/init.sql
      env:
      - name: PGPASSWORD
        valueFrom:
          secretKeyRef:
            name: aiq-credentials
            key: DB_USER_PASSWORD
      - name: DB_USER_NAME
        valueFrom:
          secretKeyRef:
            name: aiq-credentials
            key: DB_USER_NAME
      volumeMounts:
      - name: postgres-init
        mountPath: /db-init
        readOnly: true
    volumes:
    - name: postgres-init
      configMap:
        name: aiq-postgres-init
```

### ConfigMap Template from Files Directory

A dedicated template reads the SQL init script from the chart's `files/` directory using `.Files.Get`.

```yaml
{{- $postgres := index .Values.apps "postgres" }}
{{- $bootstrap := .Values.bootstrap | default dict }}
{{- $createPostgresInitConfigMap := true }}
{{- if hasKey $bootstrap "createPostgresInitConfigMap" }}
{{- $createPostgresInitConfigMap = $bootstrap.createPostgresInitConfigMap }}
{{- end }}
{{- if and $createPostgresInitConfigMap $postgres $postgres.enabled }}
apiVersion: v1
kind: ConfigMap
metadata:
  name: {{ $bootstrap.postgresInitConfigMapName | default (printf "%s-postgres-init" .Values.project.name) }}
data:
  init.sql: |
{{ .Files.Get "files/init-db.sql" | indent 4 }}
{{- end }}
```

### Idempotent Dual Database SQL Init

The SQL script is fully idempotent (`IF NOT EXISTS` / `\gexec` for conditional database creation) and initializes two databases with distinct schemas.

```sql
-- Create checkpoints database if it doesn't exist
SELECT 'CREATE DATABASE aiq_checkpoints'
  WHERE NOT EXISTS (SELECT FROM pg_database WHERE datname = 'aiq_checkpoints')\gexec

GRANT ALL PRIVILEGES ON DATABASE aiq_jobs TO aiq;
GRANT ALL PRIVILEGES ON DATABASE aiq_checkpoints TO aiq;

-- Application tables in aiq_jobs
\connect aiq_jobs
CREATE TABLE IF NOT EXISTS job_info (
    job_id VARCHAR PRIMARY KEY,
    status VARCHAR NOT NULL,
    created_at TIMESTAMP WITH TIME ZONE,
    ...
);

-- LangGraph checkpoint tables in aiq_checkpoints
\connect aiq_checkpoints
CREATE TABLE IF NOT EXISTS checkpoints (
    thread_id TEXT NOT NULL,
    checkpoint_ns TEXT NOT NULL DEFAULT '',
    checkpoint_id TEXT NOT NULL,
    checkpoint JSONB NOT NULL,
    metadata JSONB NOT NULL DEFAULT '{}',
    PRIMARY KEY (thread_id, checkpoint_ns, checkpoint_id)
);
```

## Configuration

- **Key settings:** `bootstrap.createPostgresInitConfigMap` controls whether the ConfigMap is created; `bootstrap.postgresInitConfigMapName` overrides the auto-generated name
- **Defaults:** ConfigMap creation enabled; name auto-generated as `{project.name}-postgres-init`
- **Dependencies:** PostgreSQL app must be enabled in the apps map; `aiq-credentials` Secret must exist with `DB_USER_NAME` and `DB_USER_PASSWORD` keys

## Gotchas

- The `files/init-db.sql` in the Helm chart is a copy -- the comment in the file says "KEEP IN SYNC with deploy/compose/init-db.sql (the source of truth)" -- changes must be propagated manually
- The `\gexec` psql meta-command is used for conditional database creation because PostgreSQL does not support `CREATE DATABASE IF NOT EXISTS` natively -- this only works in psql, not in other PostgreSQL clients
- The `\connect` psql command switches the active database within the script -- tables after `\connect aiq_checkpoints` are created in the checkpoints database, not the jobs database
- Without the LangGraph checkpoint tables pre-created, running backends crash with "relation checkpoints does not exist" if PostgreSQL restarts without a corresponding backend restart -- the comment in the SQL script explicitly documents this race condition
