# Dual Frontend Container Builds: Pre-Built Plugin and Multistage React UI on UBI9 nginx

## Overview

This pattern deploys two frontend container images from the same source directory using different build strategies: the OpenShift Console plugin uses pre-built assets (yarn build runs in the Makefile before docker build), while the React UI standalone app uses a full multistage Node.js build inside the Dockerfile. Both serve static assets from UBI9/nginx-120.

## Pattern Description

The `openshift-plugin/` directory contains a shared React/TypeScript codebase with two build targets: `build:plugin` for the OpenShift Console plugin and `build:react-ui` for the standalone React UI. The console plugin Dockerfile is minimal because the Makefile pre-builds assets; the React UI Dockerfile is self-contained with a multistage build. This split exists because the console plugin build must produce correct plugin manifest metadata that the Makefile's yarn build step handles.

## Implementation

### Console Plugin Dockerfile (Pre-Built Assets)

The Makefile runs `yarn build:plugin` before `docker build`, so the Dockerfile only copies pre-built assets:

```dockerfile
# openshift-plugin/Dockerfile.plugin
# Simple Dockerfile that uses pre-built assets from local yarn build
# The Makefile runs 'yarn build:plugin' before building the container image

FROM registry.access.redhat.com/ubi9/nginx-120:latest

USER 0

# Copy pre-built plugin assets (built by Makefile before docker build)
COPY dist/plugin /usr/share/nginx/html

# Ensure writable by user 1001
RUN chown -R 1001:0 /usr/share/nginx/html && \
    chmod -R g+w /usr/share/nginx/html

USER 1001

CMD ["nginx", "-g", "daemon off;"]
```

### React UI Dockerfile (Multistage Build)

The React UI Dockerfile is self-contained with a Node.js 24 builder stage:

```dockerfile
# openshift-plugin/Dockerfile.react-ui
# Build stage
FROM node:24 AS builder
WORKDIR /app
ENV NODE_OPTIONS="--max-old-space-size=4096"
COPY package.json yarn.lock ./
RUN yarn install --frozen-lockfile
COPY . .
RUN yarn build:react-ui

# Runtime stage
FROM registry.access.redhat.com/ubi9/nginx-120:latest
COPY --from=builder /app/dist/react-ui /opt/app-root/src
COPY nginx/default.conf /opt/app-root/etc/nginx.default.d/default.conf
EXPOSE 8080
CMD ["nginx", "-g", "daemon off;"]
```

### Makefile Build Targets

```makefile
# Makefile
build-console-plugin:
	@cd openshift-plugin && yarn install --frozen-lockfile
	@cd openshift-plugin && yarn build
	@$(BUILD_TOOL) buildx build --platform $(PLATFORM) \
		-f openshift-plugin/Dockerfile.plugin \
		-t $(CONSOLE_PLUGIN_IMAGE):$(VERSION) \
		openshift-plugin

build-react-ui:
	@cd openshift-plugin && yarn install --frozen-lockfile
	@cd openshift-plugin && NODE_OPTIONS="--max-old-space-size=4096" yarn build:react-ui
	@$(BUILD_TOOL) buildx build --platform $(PLATFORM) \
		-f openshift-plugin/Dockerfile.react-ui \
		-t $(REACT_UI_IMAGE):$(VERSION) \
		openshift-plugin
```

### DEV_MODE Toggle in Makefile

The Makefile's `install` target selects which frontend to deploy based on `DEV_MODE`:

```makefile
# Makefile
.PHONY: install
install: namespace pre-install-checks ...
	@if [ "$(DEV_MODE)" = "true" ]; then \
		echo "DEV_MODE=true: Installing React UI standalone application only"; \
		$(MAKE) install-react-ui NAMESPACE=$(NAMESPACE); \
	else \
		echo "DEV_MODE=false: Installing OpenShift Console Plugin only"; \
		$(MAKE) install-console-plugin NAMESPACE=$(NAMESPACE); \
	fi
```

## Configuration

- **Key settings:** `DEV_MODE` (default: false) selects console plugin or React UI at deploy time; `NODE_OPTIONS="--max-old-space-size=4096"` prevents OOM during React UI build
- **Defaults:** Console plugin serves on port 9443 (HTTPS via nginx), React UI serves on port 8080 (HTTP)
- **Dependencies:** Console plugin Dockerfile depends on `yarn build:plugin` running in Makefile before `docker build`; React UI Dockerfile is self-contained

## Gotchas

- The console plugin Dockerfile uses `/usr/share/nginx/html` as the document root (standard nginx path), while the React UI uses `/opt/app-root/src` (UBI nginx convention) -- the difference exists because the plugin Dockerfile sets up ownership explicitly while the React UI relies on UBI nginx's default directory structure
- The console plugin requires `chown -R 1001:0` and `chmod -R g+w` for OpenShift arbitrary UID support, while the React UI Dockerfile omits this (UBI nginx base image handles it for `/opt/app-root/`)
- The React UI Dockerfile copies a custom `nginx/default.conf` for SPA routing, while the console plugin uses nginx's default config (the OpenShift console handles routing)
- `NODE_OPTIONS="--max-old-space-size=4096"` is needed for both CI and Dockerfile React UI builds to prevent Node.js OOM on large TypeScript compilation
