# Tekton Camel Launcher Base Image Build

## Overview

A Tekton task pattern that builds a custom container image containing the Apache Camel CLI (`camel-launcher` JAR). This base image is used by subsequent pipeline tasks to run `camel export`, which converts Camel YAML DSL routes into compilable Quarkus projects. The task downloads the Camel launcher JAR via Maven, generates a Dockerfile and entrypoint script in the workspace, then a follow-up Buildah task builds and pushes the image to the internal OpenShift registry.

## Pattern Description

The Camel CLI is not available as a pre-built container image in the Red Hat ecosystem. This task solves that by creating a purpose-built image: it uses Maven's `dependency:copy` to fetch the versioned `camel-launcher` JAR from the Red Hat GA repository, writes a shell entrypoint script, generates a Dockerfile based on UBI10 OpenJDK 21, and prepares a build context in the workspace. The image tag matches the Camel version for traceability.

## Implementation

### Tekton Task Definition

```yaml
# deploy/tasks/09-build-camel-launcher.yaml
apiVersion: tekton.dev/v1
kind: Task
metadata:
  name: build-camel-launcher
spec:
  params:
    - name: camel-launcher-version
      type: string
      default: "4.20.0"
  workspaces:
    - name: source
  steps:
    - name: prepare-build-context
      image: registry.access.redhat.com/ubi10/openjdk-21:latest
      workingDir: $(workspaces.source.path)
      script: |
        #!/usr/bin/env bash
        set -euo pipefail
        VERSION="$(params.camel-launcher-version)"
        BUILD_DIR="camel-launcher-build"
        mkdir -p "${BUILD_DIR}"
        echo "Downloading camel-launcher-${VERSION}.jar via Maven..."
        mvn dependency:copy \
          -Dartifact=org.apache.camel:camel-launcher:${VERSION}:jar \
          -DoutputDirectory="${BUILD_DIR}" \
          -Dcom.redhat.xpaas.repo.redhatga
```

### Generated Dockerfile

The task generates a Dockerfile that installs the JAR into a dedicated directory:

```dockerfile
# Generated by deploy/tasks/09-build-camel-launcher.yaml
FROM registry.access.redhat.com/ubi10/openjdk-21:latest

ENV CAMEL_VERSION=${VERSION}
ENV CAMEL_HOME=/opt/camel

USER root
RUN mkdir -p $CAMEL_HOME/bin && chown -R 185:0 $CAMEL_HOME
USER 185

ENV PATH="$PATH:$CAMEL_HOME/bin"

COPY --chown=185:0 camel-launcher-${VERSION}.jar $CAMEL_HOME/bin/camel-launcher.jar
COPY --chown=185:0 run.sh $CAMEL_HOME/bin/camel

RUN chmod +x $CAMEL_HOME/bin/camel && \
    camel version

ENTRYPOINT ["camel"]
```

### Generated Entrypoint Script

```bash
# Generated run.sh
#!/bin/sh
exec java $JAVA_OPTS -jar "$CAMEL_HOME/bin/camel-launcher.jar" "$@"
```

### Buildah Build Step

The parent pipeline chains the Buildah cluster task to build the image:

```yaml
# deploy/pipeline/build-apps.yaml
- name: build-camel-launcher-image
  runAfter:
    - build-camel-launcher
  taskRef:
    resolver: cluster
    params:
      - name: kind
        value: task
      - name: name
        value: buildah
      - name: namespace
        value: openshift-pipelines
  params:
    - name: IMAGE
      value: image-registry.openshift-image-registry.svc:5000/$(params.namespace)/camel-launcher:$(params.camel-launcher-version)
    - name: DOCKERFILE
      value: Dockerfile
    - name: CONTEXT
      value: .
  workspaces:
    - name: source
      workspace: shared-workspace
      subPath: camel-launcher-build
```

## Configuration

- **Key settings:** `camel-launcher-version` parameter (default: `4.18.1.redhat-00016` in the pipeline, `4.20.0` in the task default); image tagged with the Camel version; uses `CAMEL_HOME=/opt/camel`
- **Defaults:** Base image is `ubi10/openjdk-21:latest` (full JDK needed for `camel export`); user ID 185; Red Hat GA Maven repository enabled via `-Dcom.redhat.xpaas.repo.redhatga`
- **Dependencies:** Maven must be available in the build step image; the Red Hat GA Maven repository must be accessible; workspace subPath `camel-launcher-build` isolates the build context

## Gotchas

- The version suffix `.redhat-00016` in `camel-launcher-version` indicates a Red Hat productized build of Apache Camel -- this is downloaded from the Red Hat GA Maven repository, not Maven Central
- The `camel version` command at the end of the Dockerfile serves as a smoke test -- if the JAR is corrupt or the entrypoint is misconfigured, the build fails here
- The Buildah task uses `TLS_VERIFY: "false"` because the internal OpenShift registry uses a self-signed certificate from the service CA
- The workspace `subPath: camel-launcher-build` ensures the Buildah task sees only the generated build context, not the full workspace contents
