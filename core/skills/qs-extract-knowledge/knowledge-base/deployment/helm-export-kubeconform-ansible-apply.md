# Helm Export with Kubeconform Validation and Ansible Apply

## Overview

This pattern exports Helm chart templates to static YAML manifests, validates them offline using kubeconform (no cluster required), and optionally applies them via an Ansible playbook. This enables CI validation of Helm output without needing a running cluster, and provides an Ansible-based deployment path alongside `helm install`.

## Pattern Description

The `helm-export-demo` Makefile target runs `helm template` with the demo values overlays, writes the rendered manifests to `ansible/helm-export/`, and adds any extra secrets not generated by Helm (e.g., ServiceNow credentials). The `helm-export-validate-demo` target chains the export and runs kubeconform for schema validation. The `ansible-apply-demo` target exports and then applies via an Ansible playbook targeting the specified namespace.

## Implementation

### Helm Export Target

```makefile
# Makefile (excerpt)
HELM_EXPORT_DIR ?= ansible/helm-export

helm-export-demo: helm-depend
	$(call helm_export,\
		-f helm/values-test.yaml \
		-f helm/values-demo.yaml \
		$(helm_demo_email_args) \
		$(PROMPT_OVERRIDES))
	@kubectl create secret generic $(MAIN_CHART_NAME)-servicenow-credentials \
		--from-literal=servicenow-instance-url="$${SERVICENOW_INSTANCE_URL:-http://self-service-agent-mock-servicenow:8080}" \
		--from-literal=servicenow-api-key="$${SERVICENOW_API_KEY:-now_mock_api_key}" \
		-n $(NAMESPACE) --dry-run=client -o yaml > $(HELM_EXPORT_DIR)/servicenow-credentials-secret.yaml
```

### Kubeconform Validation (No Cluster)

```makefile
# Makefile (excerpt)
helm-export-validate-demo: helm-export-demo
	@command -v kubeconform >/dev/null 2>&1 || { \
		echo "Error: kubeconform not found."; exit 1; }
	@kubeconform -summary -ignore-missing-schemas $(HELM_EXPORT_DIR)/
```

### CI Integration

The PR checks workflow validates Helm output without any cluster:

```yaml
# .github/workflows/pr-checks.yml (excerpt)
helm-export-validate:
  steps:
    - uses: azure/setup-helm@v4
      with:
        version: "v3.17.0"
    - uses: bmuschko/setup-kubeconform@v1
    - run: make helm-export-validate-demo
      env:
        NAMESPACE: ci-demo
        HF_TOKEN: mock_hf_token_for_ci
```

### Ansible Apply Path

```makefile
# Makefile (excerpt)
ansible-apply-demo: check-ansible helm-export-demo
	ansible-playbook -i localhost, ansible/playbooks/apply-demo-manifests.yml \
		-e "helm_export_dir=$(HELM_EXPORT_DIR)" \
		-e "target_namespace=$(NAMESPACE)"
```

## Configuration

- **Key settings:** `HELM_EXPORT_DIR` defaults to `ansible/helm-export/`; `NAMESPACE` and `HF_TOKEN` are required for export (can be mock values for CI validation)
- **Defaults:** The export uses values-test.yaml and values-demo.yaml overlays; kubeconform runs with `-ignore-missing-schemas` for CRDs not in the default schema registry
- **Dependencies:** Requires Helm CLI for template rendering; kubeconform for validation; ansible-playbook for the apply path (checked by `check-ansible` prerequisite)

## Gotchas

- The export adds a ServiceNow credentials secret via `kubectl create secret --dry-run=client -o yaml` since this secret is created imperatively by `helm_install_common` and not rendered by Helm templates (see `Makefile` `helm-export-demo`)
- Kubeconform uses `-ignore-missing-schemas` because custom CRDs (Knative Triggers, Strimzi Kafka, NemoGuardrails) do not have schemas in the default registry
- The CI job uses mock values (`HF_TOKEN: mock_hf_token_for_ci`, `NAMESPACE: ci-demo`) since export and validation do not need real credentials or a real cluster
