# React UI App

## Overview

A React-based frontend that operates in two deployment modes from a single codebase: as an OpenShift Console dynamic plugin (integrated into the admin console under Observe) and as a standalone single-page application served by nginx. It uses PatternFly 5 for the UI component library and communicates with a backend MCP server for AI-powered observability features including vLLM metrics analysis, OpenShift cluster monitoring, and chat-based Prometheus queries.

## Tech Stack & Dependencies

- **Runtime:** Node.js 24, React 17, TypeScript 5
- **Container image:** `quay.io/ecosystem-appeng/aiobs-react-ui` (multi-stage build: node:24 builder + `registry.access.redhat.com/ubi9/nginx-120:latest`)
- **Key dependencies:**
  - `@patternfly/react-core` ^5.0.0, `@patternfly/react-charts` ^7.0.0, `@patternfly/react-table` ^5.0.0
  - `@openshift-console/dynamic-plugin-sdk` ^1.6.0 (console plugin mode)
  - `@openshift-console/dynamic-plugin-sdk-webpack` ^1.3.0 (plugin webpack integration)
  - `react-markdown` ^8.0.7 with `remark-gfm` (rendering AI analysis responses)
  - `react-router-dom` ^5.3.4 (SPA routing)
- **Helm subchart:** `deploy/helm/react-ui-app/` (standalone chart, not a subchart)

## Key Patterns

### Dual-Mode Architecture (Plugin + Standalone SPA)

The codebase supports two build targets from separate webpack configs sharing a common base. Core business logic lives in `src/core/` and is shared; mode-specific entry points live in `src/plugin/` and `src/react-ui/`.

```typescript
// src/shared/config.ts - Runtime mode detection
export const getDeploymentMode = (): 'plugin' | 'react-ui' => {
  if (typeof window !== 'undefined') {
    const isPluginContext = window.location.pathname.startsWith('/observe/ai-observability');
    const hasConsoleAPI = !!(window as any).OPENSHIFT_CONSOLE_PLUGIN_API;
    if (isPluginContext || hasConsoleAPI) {
      return 'plugin';
    }
  }
  return 'react-ui';
};
```

The plugin build uses `ConsoleRemotePlugin` from the SDK with no explicit entry points (generated by the plugin), while the standalone build uses `HtmlWebpackPlugin` with a standard React entry point at `src/react-ui/index.tsx`.

### OpenShift Console Dynamic Plugin Registration

The plugin registers navigation items and page routes under the admin perspective's "Observe" section via `console-extensions.json`:

```json
[
  {
    "type": "console.navigation/href",
    "properties": {
      "id": "ai-observability",
      "perspective": "admin",
      "section": "observe",
      "name": "%plugin__aiobs-console-plugin~AI Observability%",
      "href": "/observe/ai-observability"
    }
  },
  {
    "type": "console.page/route",
    "properties": {
      "path": "/observe/ai-observability",
      "component": { "$codeRef": "AIObservabilityPage" }
    }
  }
]
```

Exposed modules are declared in `package.json` under `consolePlugin.exposedModules`, and the plugin entry point (`src/plugin/index.ts`) re-exports the shared page components.

### MCP Client with Mode-Aware URL Resolution

The frontend communicates with the backend MCP server using JSON-RPC 2.0 over HTTP. The MCP URL is resolved differently depending on deployment mode:

```typescript
// src/shared/config.ts
export const getMcpServerUrl = (): string => {
  const mode = getDeploymentMode();
  const isLocalDev = window.location.hostname === 'localhost';

  if (isLocalDev) return 'http://localhost:8085/mcp';
  if (mode === 'plugin') return '/api/proxy/plugin/aiobs-console-plugin/mcp/mcp';
  return '/api/mcp'; // React UI uses nginx proxy
};
```

The MCP client (`src/core/services/mcpClient.ts`) handles multiple response formats from the server -- `structuredContent.result` as string, array, or object, and `content` arrays with text objects.

### Runtime Config Initialization

The app fetches runtime configuration (e.g., dev mode flag) from the MCP server's `/config` endpoint before rendering. This prevents race conditions where components would try to use config before it is available:

```typescript
// src/react-ui/App.tsx
React.useEffect(() => {
  const loadConfig = async () => {
    try {
      await initializeRuntimeConfig();
      setConfigLoaded(true);
    } catch (error) {
      console.error('[App] Failed to initialize runtime config:', error);
      setConfigLoaded(true); // Still render even if config fails
    }
  };
  loadConfig();
}, []);

if (!configLoaded) {
  return <div>Loading configuration...</div>;
}
```

The `runtimeConfig.ts` service uses promise caching to prevent duplicate fetches when multiple components call `fetchRuntimeConfig()` simultaneously.

### GPU-Aware Navigation

Navigation items are conditionally shown based on GPU availability detected at startup. The app queries device metrics (DCGM for NVIDIA, Intel Gaudi) and caches the result for 5 minutes:

```typescript
// src/react-ui/Navigation.tsx
const navItems = gpuAvailable === true
  ? allNavItems
  : allNavItems.filter(item => !item.requiresGpu);
```

### Dev Mode Credential Management

In dev mode (determined by the MCP server's `/config` endpoint), API keys are stored in browser `sessionStorage` rather than Kubernetes secrets. The `injectDevCredentials` function in `mcpClient.ts` auto-injects cached API keys into MCP tool calls, detecting the provider from model ID patterns:

```typescript
// src/core/services/mcpClient.ts
const patterns: Record<string, RegExp> = {
  openai: /^(openai\/|gpt-)/,
  anthropic: /^(anthropic\/|claude-)/,
  google: /^(google\/|gemini-)/,
  meta: /^(meta\/|llama-)/,
  maas: /^maas\//,
};
```

### OAuth Proxy Sidecar for Authentication

The Helm chart deploys an `origin-oauth-proxy` sidecar container alongside the nginx-served React UI. The proxy handles OpenShift authentication and terminates TLS, forwarding authenticated requests to the UI on localhost:

```yaml
# deploy/helm/react-ui-app/values.yaml
oauth:
  enabled: true
  image:
    repository: "quay.io/openshift/origin-oauth-proxy"
    tag: 4.22.0
  port: 8443
  upstreamTimeout: "240s"
```

The service account is annotated with an OAuth redirect reference, and the serving cert is auto-provisioned by OpenShift's service-serving-cert-signer.

## Configuration

- **Environment variables:**
  - `MCP_SERVER_URL` -- injected by the Helm deployment template, points to the MCP server's cluster-internal service URL (e.g., `http://aiobs-mcp-server-svc.<namespace>.svc.cluster.local:8085/mcp`)
  - `NODE_OPTIONS="--max-old-space-size=4096"` -- required during build to avoid OOM with webpack
- **Config files:**
  - `console-extensions.json` -- defines plugin navigation and page routes for the OpenShift Console
  - `nginx/default.conf` -- SPA routing, MCP proxy, and static asset caching rules
  - `config/webpack.common.ts` -- shared webpack rules with path aliases (`@core`, `@shared`)
  - `config/webpack.plugin.ts` -- Console plugin build with `ConsoleRemotePlugin`
  - `config/webpack.react-ui.ts` -- Standalone SPA build with `HtmlWebpackPlugin`
- **Helm values:**
  - `app.image.repository/tag` -- container image coordinates
  - `oauth.enabled` -- toggles the OAuth proxy sidecar (default: `true`)
  - `oauth.upstreamTimeout` / `route.timeout` -- set to `240s` for long-running AI analysis requests
  - `mcpServer.serviceName/port/namespace` -- MCP server connection details
  - `route.tls.termination` -- automatically set to `reencrypt` when OAuth is enabled

## Known Gotchas

- **Two Dockerfiles exist:** `Dockerfile.react-ui` performs a multi-stage build (node builder + nginx runtime) for the standalone SPA. `Dockerfile.plugin` expects pre-built assets from a local `yarn build:plugin` run (the Makefile calls build before `docker build`). Mixing them up produces broken images.
- **React 17 pinned via resolutions:** The `package.json` uses `resolutions` to pin `react`, `react-dom`, `@types/react`, and `@types/react-dom` to `^17.0.2`. This is required for compatibility with `@openshift-console/dynamic-plugin-sdk` which does not yet support React 18.
- **Plugin webpack excludes `src/react-ui/`:** The plugin webpack config (`config/webpack.plugin.ts`) explicitly excludes `src/react-ui/` from ts-loader to prevent the standalone SPA shell from being bundled into the console plugin.
- **Nginx proxy uses `proxy_ssl_verify off`:** The `nginx/default.conf` disables SSL verification when proxying to the MCP server because the internal service uses OpenShift's auto-generated serving certificates which nginx does not trust by default.
- **Route TLS termination changes with OAuth:** When `oauth.enabled=true`, the route template switches from `edge` to `reencrypt` termination because the OAuth proxy sidecar terminates TLS itself and re-encrypts traffic to the route.
- **ESM modules in Jest:** The `jest.config.js` has a long `transformIgnorePatterns` exclusion list for `remark-gfm` and its transitive ESM dependencies. Without this, Jest cannot parse the ESM-only modules.
- **Promise caching in runtimeConfig:** The `fetchRuntimeConfig()` function caches the in-flight promise to prevent duplicate network calls when multiple React components request config simultaneously during initialization.

## Testing Notes

- **Unit tests:** Jest with `jsdom` environment, using `@testing-library/react`. Run with `yarn test`. Coverage thresholds set to 50% statements/lines/functions, 40% branches.
- **Integration tests:** Cypress-based tests in `integration-tests/` directory targeting the running UI.
- **Dev environment:** A devcontainer setup (`docker-compose.yml`) spins up the OpenShift Console bridge alongside the plugin, requiring `dev.env` with `OC_URL`, `OC_USER`, `OC_PASS`.
- **Health check:** The nginx config exposes `/health` returning 200 with "healthy\n". The Helm deployment uses this for both liveness (30s initial delay) and readiness (5s initial delay) probes.
