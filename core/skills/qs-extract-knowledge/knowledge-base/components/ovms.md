# OpenVINO Model Server (OVMS)

## Overview

OpenVINO Model Server (OVMS) serves YOLO object detection models exported from PyTorch (.pt) to OpenVINO IR format. In this quickstart it runs in multi-model mode via a generated `config.json`, serving multiple detection models (e.g., PPE, bird) through a single gRPC endpoint. On OpenShift it is deployed as a KServe ServingRuntime backed by the Red Hat OVMS image; locally it runs as a container in Podman compose with a shared named volume for model artifacts.

## Tech Stack & Dependencies
- **Runtime:** OpenVINO Model Server (container image)
- **Container image (OpenShift):** `registry.redhat.io/rhoai/odh-openvino-model-server-rhel9@sha256:7daebf4a...`
- **Container image (local):** `docker.io/openvino/model_server@sha256:471362689b...`
- **Model export image:** `docker.io/ultralytics/ultralytics@sha256:6ec3f66f...`
- **Key dependencies:** `ovmsclient` (Python gRPC client), MinIO (model storage on OpenShift), Ultralytics YOLO + CLIP (model export)
- **Protocols:** gRPC (port 8081 local / 9000 on OpenShift), REST (port 8080 local / 8888 on OpenShift)

## Key Patterns

### Multi-Model config.json Generation

OVMS multi-model mode uses a `config.json` file that lists all models with per-model tuning. This file is generated dynamically by `export_models.py` (cluster) or `yolo-model-prep.sh` (local), not hand-written.

```python
# From app/data-image/export_models.py — write_ovms_config_json()
model_cfg: dict = {
    "name": name,
    "base_path": f"{mount_base.rstrip('/')}/{name}",
}
model_cfg.update(_ovms_per_model_extras())
entries.append({"config": model_cfg})
# ...
cfg = {"model_config_list": entries}
```

Per-model tuning fields (`nireq`, `plugin_config`, `shape`, `target_device`, `batch_size`) are driven by environment variables:

```yaml
# From deploy/local/podman-compose.yaml — yolo-model-prep service
environment:
  OVMS_CONFIG_NIREQ: "8"
  OVMS_CONFIG_PLUGIN_CONFIG: '{"PERFORMANCE_HINT": "THROUGHPUT", "ENABLE_CPU_PINNING": false}'
  OVMS_CONFIG_SHAPE: '{"x":"(-1,3,640,640)"}'
```

### YOLO PyTorch to OpenVINO IR Export

The model preparation pipeline exports `.pt` YOLO weights to OpenVINO IR format (`.xml` + `.bin`) using the Ultralytics CLI. Each model lands in the OVMS directory layout `ovms/<stem>/1/<stem>.xml`.

```bash
# From deploy/local/yolo-model-prep.sh
yolo export "model=/tmp/${stem}.pt" format=openvino task=detect dynamic=True
cp "/tmp/${stem}_openvino_model/"*.xml "$target_xml"
cp "/tmp/${stem}_openvino_model/"*.bin "${target_dir}/${stem}.bin"
```

The script is idempotent: if `<stem>.xml` already exists it skips re-export. The stem `custome_ppe` is explicitly excluded.

### gRPC Client Inference with ovmsclient

The backend uses the `ovmsclient` Python library for gRPC inference. Each inference worker thread owns its own `Runtime` instance to avoid sharing gRPC stubs or preprocessing buffers.

```python
# From app/backend/runtime.py
from ovmsclient import make_grpc_client

# Local mode:
self._grpc_client = make_grpc_client(self.service_url)

# Inference call:
inputs = {self.input_name: image}
return self._grpc_client.predict(
    inputs, self.model_name, self.model_version,
    timeout=self._ovms_predict_timeout,
)
```

### Batched Inference

The `InferencePool` sends batched frames as a single `(N, 3, 640, 640)` tensor in one gRPC call. Batch size is configurable via `INFERENCE_MIN_BATCH` / `INFERENCE_MAX_BATCH` environment variables (default: 3).

```python
# From app/backend/video_processing/inference.py
class InferencePool:
    """Pool of daemon threads that run OVMS inference on frames
    from an input queue. Each worker owns its own Runtime instance."""
```

### KServe ServingRuntime on OpenShift

On OpenShift, OVMS is deployed as a KServe `ServingRuntime` + `InferenceService` via a deployer Job (`create_runtime.py`). The multi-model variant uses `--config_path` pointing to the config.json uploaded to MinIO.

```python
# From app/runtime/create_runtime.py — _build_ovms_args()
if cfg.get("multi_model_serving") and cfg["runtime_type"] == "openvino":
    return [
        "--config_path=/mnt/models/config.json",
        f"--port={cfg['grpc_port']}",
        f"--rest_port={cfg['rest_port']}",
        *common_tail_config_file,
    ]
```

### OpenShift gRPC URL Mapping

KServe predictor Services expose HTTP on port 80 and OVMS gRPC on port 9000. The backend maps the app config's HTTP model URL to a gRPC address automatically.

```python
# From app/backend/openshift_grpc_url.py
def model_url_to_ovms_grpc(model_url: str) -> str:
    # KServe predictor: HTTP on default 80; OVMS gRPC on 9000
    p = urlparse(parse_src)
    if p.hostname and p.scheme in ("http", "https"):
        port = p.port
        if port is not None and port not in (80, 443):
            return _grpc_host_port(p.hostname, port)
        return _grpc_host_port(p.hostname, 9000)
```

### Local Podman Compose Deployment

Locally, OVMS runs as a container in Podman compose with a shared `model_repo` named volume. A `yolo-model-prep` init service exports models before OVMS starts.

```yaml
# From deploy/local/podman-compose.yaml
ovms:
  image: docker.io/openvino/model_server@sha256:471362689b...
  depends_on:
    yolo-model-prep:
      condition: service_completed_successfully
  command:
    - --config_path
    - /models/ovms/config.json
    - --port
    - "8081"
    - --rest_port
    - "8080"
  volumes:
    - model_repo:/models:z
  healthcheck:
    test: ["CMD", "curl", "-f", "http://localhost:8080/v2/health/ready"]
```

## Configuration
- **Environment variables:**
  - `OVMS_CONFIG_NIREQ` -- Number of inference requests per model (default: 2 cluster, 8 local)
  - `OVMS_CONFIG_PLUGIN_CONFIG` -- JSON object for OpenVINO plugin configuration (default: `{"PERFORMANCE_HINT": "THROUGHPUT"}`)
  - `OVMS_CONFIG_SHAPE` -- Per-model tensor shape override (e.g., `{"x":"(-1,3,640,640)"}`)
  - `OVMS_CONFIG_TARGET_DEVICE` -- Target device override (optional)
  - `OVMS_CONFIG_BATCH_SIZE` -- Batch size override (optional)
  - `OVMS_CLUSTER_MOUNT_BASE` -- Mount path for models on OpenShift (default: `/mnt/models`)
  - `MODEL_INPUT_NAME` -- Tensor input name (default: `x`)
  - `MODEL_VERSION` -- Model version string (default: `1`)
  - `OVMS_GRPC_TIMEOUT` -- gRPC predict deadline in seconds (default: `20`, Helm default: `60`)
  - `RUNTIME_TYPE` -- Selects runtime: `openvino` for OVMS, `kserve` for Triton
  - `INFERENCE_WORKERS` -- Number of parallel inference worker threads (default: 2)
- **Config files:** `config.json` (generated, lists all models with tuning parameters)
- **Helm values:** `modelServing.runtimeType`, `modelServing.openvino.*`, `runtimeDeployer.*`

## Known Gotchas
- **`--config_path` and per-model CLI flags are mutually exclusive:** When OVMS uses `--config_path` (multi-model mode), CLI flags like `--nireq`, `--plugin_config`, `--batch_size`, and `--shape` cause OVMS to exit with "Model parameters in CLI are exclusive with the config file". Tuning must go into `config.json` instead. The code explicitly uses a separate `common_tail_config_file` list that omits these flags (comment in `create_runtime.py`).
- **Multi-model OVMS + KServe RawDeployment args conflict:** KServe RawDeployment merges ServingRuntime args with per-model template args (`--model_name`, `--model_path`). For multi-model OVMS (which only uses `--config_path`), the InferenceService spec must override `predictor.model.args` to replace the merged list entirely (see `build_inference_service_spec` in `create_runtime.py`).
- **Mount path differs between local and cluster:** Local Podman compose mounts the volume at `/models` while KServe on OpenShift mounts at `/mnt/models`. The `config.json` `base_path` must match the actual mount. `OVMS_CLUSTER_MOUNT_BASE` env var controls this (default: `/mnt/models`).
- **OpenShift random-UID SCC breaks in-place config regeneration:** The baked-in `config.json` under `/upload` is owned by root and read-only under OpenShift's random-UID SCC. The `upload.sh` regeneration writes to `/tmp` instead (comment in `upload.sh`).
- **gRPC port 9000 vs REST port 80 on KServe:** The KServe predictor Service exposes HTTP on port 80 but OVMS gRPC on 9000. The `ovmsclient` library requires gRPC, so the backend must map HTTP URLs to the gRPC port. CPU OVMS on OpenShift often needs a timeout greater than 10 seconds on cold start; the Helm default is 60 seconds.
- **`custome_ppe` stem excluded:** Both `yolo-model-prep.sh` and `export_models.py` skip the `custome_ppe.pt` weight file, with `import_model_weight.py` explicitly blocking it with an error message.

## Testing Notes
- Verify OVMS health with `curl http://localhost:8080/v2/health/ready` (local) or the healthcheck probe on OpenShift
- After model export, confirm `config.json` lists the expected number of models by checking the log output: "Wrote /models/ovms/config.json with N model(s)"
- Use `import_model_weight.py` to add or replace individual model weights locally without rebuilding the data image
- On OpenShift, check the InferenceService status: `kubectl get isvc <name> -n <namespace>` for Ready condition
