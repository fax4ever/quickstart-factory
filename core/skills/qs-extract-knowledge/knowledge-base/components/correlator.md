# Correlator

## Overview

The correlator is an Apache Camel application that consumes OpenTelemetry logs and traces from Kafka topics, correlates them by traceId using Infinispan as a distributed cache, and detects error events. When cached telemetry data expires after a configurable TTL, error traceIds are forwarded to a JMS queue for downstream analysis by an LLM-based analyzer. The component is written entirely in Camel YAML DSL (no Java source code) and uses Kaoto DataMapper for visual schema-to-schema transformations.

## Tech Stack & Dependencies

- **Runtime:** Apache Camel JBang (dev), exported to Quarkus for production (Quarkus 3.33.2.redhat-00002)
- **Container image:** Built via Tekton pipeline using `camel export --runtime=quarkus`, Maven build, then Buildah; pushed to OpenShift internal registry
- **Key dependencies:** camel-kafka, camel-infinispan, camel-jms, camel-observability-services, camel-quarkus-platform-http, artemis-jakarta-client-all (2.44.0), quarkus-pooled-jms (2.12.0), xslt-saxon
- **Helm subchart:** No dedicated subchart; deployed via a shared Helm chart using a generic `components` range in `chart/templates/deployment.yaml`

## Key Patterns

### Camel YAML DSL Routes (No Java Code)

The entire component is defined in three `.camel.yaml` files with no compiled Java source. Routes are designed in the Kaoto visual editor and run via `camel run` locally or exported to Quarkus for production.

```yaml
# Running locally (from src/correlator/README.md)
camel run *.camel.yaml *.xsl *.json --dev --prop=application-dev.properties

# Exporting for production
camel export --runtime=quarkus --directory=./quarkus *.camel.yaml *.xsl *.json
```

### Kafka Consumer with JSONPath Splitting

Logs and traces are consumed from separate Kafka topics and split into individual records using JSONPath before mapping. The `groupId` is set to `correlator` for both consumers.

```yaml
# From logs-mapper.camel.yaml
- route:
    id: log-consumer
    from:
      uri: kafka:{{camel.kafka.topic.logs}}
      parameters:
        autoOffsetReset: earliest
        groupId: correlator
      steps:
        - split:
            expression:
              jsonpath:
                expression: $.resourceLogs[*].scopeLogs[*].logRecords[*]
                writeAsString: true
```

### Kaoto DataMapper XSLT Transformations

Raw OTel JSON payloads are transformed into a simplified correlated format using XSLT generated by the Kaoto visual editor. The `.kaoto` file at repo root maps source/target JSON schemas to the generated XSL files. The pattern passes the JSON as a Camel header parameter, inserts a dummy XML body, then applies the XSLT via `xslt-saxon`.

```yaml
# From logs-mapper.camel.yaml — the dummy XML + XSLT pattern
- setHeader:
    name: logs
    expression:
      simple:
        expression: ${body}
- setBody:
    expression:
      constant:
        expression: <dummy/>
- step:
    id: kaoto-datamapper-4a94acc3
    steps:
      - to:
          uri: xslt-saxon:kaoto-datamapper-4a94acc3.xsl
          parameters:
            allowStAX: true
```

### Infinispan Cache Correlation by traceId

Records are stored in the `events` cache keyed by `otel-{traceId}`. On each new record, the route GETs existing records, appends the new one sorted by `timeUnixNano` using jq, and PUTs back. The Camel `claimCheck` EIP preserves the current body across cache operations.

```yaml
# From infinispan.camel.yaml — append-and-sort pattern
- setBody:
    jq:
      expression: (variable("existingRecords") | fromjson) + [.] |
        sort_by(.timeUnixNano)
      resultType: java.lang.String
```

### Error Detection and Deferred Processing via Cache Expiry

Error events are detected by checking `severityText == "error"` (case-insensitive) or `status == "2"` using a jq expression. Matching traceIds are written to a separate `events-to-process` cache with a short TTL (20 seconds). When that cache entry expires, Infinispan fires a `CLIENT_CACHE_ENTRY_EXPIRED` event that the correlator listens to, forwarding the traceId to the JMS `error-logs` queue.

```yaml
# From infinispan.camel.yaml — error detection filter
- choice:
    when:
      - jq:
          expression: (.severityText // "" | ascii_downcase) == "error" or .status == "2"
        steps:
          - to:
              uri: infinispan:events-to-process
              parameters:
                operation: PUTIFABSENT

# Cache expiry listener triggers JMS send
- route:
    id: route-expired-events
    from:
      uri: infinispan:events-to-process
      parameters:
        eventTypes: CLIENT_CACHE_ENTRY_EXPIRED
      steps:
        - to:
            uri: jms:{{camel.jms.queue.error-logs}}
```

### Per-Trace AI Prompt Management

The correlator also manages per-trace custom prompts via an `ai-messages` Infinispan cache. Prompts are received from JMS, stored with key `{traceId}-prompt-msg`, and retrieved with a fallback to a default `prompt-msg` key.

```yaml
# From infinispan.camel.yaml — prompt read with fallback
- choice:
    when:
      - simple: "${body} == null || ${body} == ''"
        steps:
          - setHeader:
              name: CamelInfinispanKey
              constant: prompt-msg
          - to:
              uri: infinispan:ai-messages
              parameters:
                operation: GET
```

## Configuration

- **Environment variables (production):**
  - `KAFKA_BROKERS` — Kafka bootstrap servers (default: `kafka:9092`)
  - `INFINISPAN_HOSTS` — Infinispan Hot Rod endpoint (default: `infinispan:11222`)
  - `DATAGRID_USERNAME` / `DATAGRID_PASSWORD` — Infinispan credentials (from `infra-accounts` secret)
  - `AMQ_USERNAME` / `AMQ_PASSWORD` — Artemis JMS credentials (from `infra-accounts` secret)
  - `ARTEMIS_BROKER_URL` — Artemis broker URL (default: `tcp://artemis:61616`)
- **Config files:**
  - `application-dev.properties` — local dev config with hardcoded localhost endpoints
  - `chart/properties/correlator/application-prod-quarkus.properties` — production config mounted via ConfigMap with `${ENV_VAR}` placeholders
- **Helm values:** Under `components.correlator` in `chart/values.yaml`
  - `replicas: 1`, `memoryLimit: 512Mi`, `strategy: RollingUpdate`, `expose: false`
- **Kafka topics:** `otlp_logs` (logs), `otlp_spans` (traces)
- **JMS queues:** `error-logs` (outbound error traceIds), `ai-prompts` (inbound custom prompts), `ai-prompts-read` (prompt read requests)
- **Infinispan caches:**
  - `events` — correlated telemetry records, TTL 600000ms (10 minutes)
  - `events-to-process` — error traceIds pending analysis, TTL 20000ms (20 seconds)
  - `ai-messages` — per-trace and default AI prompts, no TTL

## Known Gotchas

- **Standalone Camel metrics disabled in Quarkus mode:** The production properties file explicitly sets `camel.metrics.enabled=false` and `camel.management.enabled=false` with the comment "not compatible with Quarkus" (`application-prod-quarkus.properties` line 33-35). The dev properties enable them. Quarkus uses its own Micrometer integration instead via `quarkus-micrometer` and `camel-observability-services`.
- **Netty native transport workaround:** The Helm values include `nettyWorkaround: true` with `javaOptsAppend: "-Dio.netty.transport.noNative=true"` applied as `JAVA_OPTS_APPEND` on the container, indicating a known issue with Netty native transport on OpenShift (`chart/values.yaml` lines 40-41).
- **Dummy XML body for Kaoto DataMapper:** The XSLT-based data mapping requires an XML body input, so the route sets a `<dummy/>` XML body and passes the actual JSON as a header parameter. This is a Kaoto DataMapper convention, not an obvious pattern.
- **PUTIFABSENT for error dedup:** The `events-to-process` cache uses `PUTIFABSENT` rather than `PUT` to avoid resetting the TTL on duplicate error entries for the same traceId (`infinispan.camel.yaml` line 124).
- **Infinispan SASL auth required:** Both dev and prod configurations require `DIGEST-MD5` SASL authentication with `security-realm=default` and `security-server-name=infinispan`. The prod config also requires `quarkus.infinispan-client` properties for the Quarkus Infinispan extension.
- **Tekton build exports with explicit deps:** The `camel export` in the Tekton pipeline requires explicitly listing dependencies via `--dep` since Camel JBang auto-resolution does not carry over: `camel-jms,camel-observability-services,mvn:org.apache.camel.quarkus:camel-quarkus-platform-http,mvn:org.apache.activemq:artemis-jakarta-client-all:2.44.0,mvn:io.quarkiverse.messaginghub:quarkus-pooled-jms:2.12.0` (`deploy/pipeline/build-apps.yaml`).
- **JMS connection pooling:** Artemis connections use `JmsPoolConnectionFactory` with `maxSessionsPerConnection=500` and `connectionIdleTimeout=20000` to handle high-throughput message flow (`application-dev.properties` lines 21-24).

## Testing Notes

- Run locally with `camel run *.camel.yaml *.xsl *.json --dev --prop=application-dev.properties` from `src/correlator/`
- Requires local Kafka (port 9092), Infinispan (port 11222), and Artemis (port 61616) instances
- Infinispan caches must be created before the correlator starts; the `create.sh` script iterates over `deploy/resources/infinispan/caches/*.json` and creates them via the Infinispan REST API
- Health endpoints on port 9876: `/observe/health/started`, `/observe/health/live`, `/observe/health/ready`
- Prometheus metrics scraped from `/observe/metrics` on port 9876 via ServiceMonitor
- Custom Micrometer counters: `correlator.events.stored` (tagged by record type), `correlator.errors.detected`, `correlator.events.expired`
- PrometheusRule alert `ErrorDetected` fires when `increase(correlator_errors_detected_total[1m]) > 0`
